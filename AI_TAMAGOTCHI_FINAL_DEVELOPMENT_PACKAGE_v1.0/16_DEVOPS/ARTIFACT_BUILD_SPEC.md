# RELEASE ARTIFACT BUILD SPECIFICATION

## Build-once / promote-many

The same immutable artifacts tested as release candidate are promoted to production.

Do not rebuild application binaries for production after staging approval.

## Required release artifacts

At minimum:

1. backend OCI image/artifact;
2. web immutable static artifact or web OCI image;
3. database migration bundle;
4. `openapi_final_v1.yaml`;
5. runtime configuration schema;
6. feature-flag baseline;
7. game-rule configuration/version;
8. visual runtime asset manifest/reference generated by implementation;
9. build manifest;
10. checksums/digests.

Worker uses the same backend image as API with a different entrypoint.

## Build manifest fields

```text
release_id
source_revision
build_timestamp
node_version
pnpm_version
lockfile_sha256
backend_artifact_digest
web_artifact_digest
openapi_sha256
migration_bundle_sha256
runtime_config_schema_sha256
feature_flags_sha256
game_config_sha256
visual_runtime_manifest_sha256
test_evidence_ref
security_scan_evidence_ref
```

Null is allowed only where the item is explicitly non-applicable; a required production artifact cannot be silently omitted.

## Reproducibility

Repository must pin:
- Node exact patch;
- pnpm exact version;
- lockfile;
- container base-image digest/version;
- generated API client source checksum.

Build must fail rather than silently resolve an unreviewed major-version change.

## Security checks

Before artifact promotion:
- secret scan;
- dependency vulnerability scan;
- dependency/license inventory/check;
- built frontend secret scan;
- image/artifact scan where tooling supports it;
- verify no `.env`/local credentials;
- verify no raw input/employee fixture data in release artifact;
- verify no proxy GLB falsely listed as final production asset.

Exact scanners are CI-vendor/tool choices and remain provider-neutral.
